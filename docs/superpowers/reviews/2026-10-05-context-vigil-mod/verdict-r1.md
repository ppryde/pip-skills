## Rejected findings (NOT REAL for this merge), with reasons

- **S7 / O10 — phone notices and countdown never reach the phone.** Known, accepted limit for this merge; fixed on `feat/cvm-phone-prompting`. (PROBES §1, SMOKES #4 record it.)
- **S10 — a draft-waiting attended clear lands on the message the person just sent.** By design: spec §2 "Requested handovers are attended by definition" and the existing test `shell-handover.test.tsx:176` ("a prompt does not stop its clear"). The draft guard protects an unsent message only. If the owner wants "wait for the turn to end", that is a new rule, not a defect.
- **S11 — interlock sees only the account `settings.json`; regex needs a closing quote.** Matches spec §7 exactly (account `settings.json` OR a classic session record). Classic's installer writes `f'"{launcher}" hook {name}'` (`skills/context-vigil/scripts/context_vigil/install.py:177`) — quoted, as the regex expects — and keeps `<root>/sessions/<id>.json` (`paths.py:480`), which `classicSessionPath` mirrors. Classic is user-level only by its own spec.
- **S13 / O8(sticky `headless`)** — spec §2: "A session whose prompts come from `sdk` is unattended from its first turn." The typings define `sdk` as the SDK host's own turn (`claude -p`); no evidence of a session mixing `sdk` and `composer`. The `unclassified` half is kept as R1-24.
- **S18 — 64 KiB tail may miss the latest `cache_creation`.** Owner-approved ruling in PROBES §11: "No widening, no retry"; the skip is logged (`last_light.skip ttl-unknown`).
- **S22 — `$.ui.ask` may never resolve on the phone.** Superseded by the Field Notes doc: "Yes: it can be answered on the phone and resolves with the chosen label (verified 2026-10-04)", and an open ask raises Remote Control's "action required" push. PROBES §6's "phone pending" is stale and should be updated.
- **S16 / O13 — early stop re-fires per process / per reload.** Ruled per session (ledger F4/F5: "a restarted process loses the mark (may re-fire once)"; README "early-stop marks are per running session"; code comment at register:54-55). The resume timer dying on a reload is recovered by that same re-fire. Only the doc drift survives, as R1-26.
- **O16(b) — a non-human prompt (task-notification etc.) cancels the RC countdown.** Spec §2: "any `prompt.submit` during the countdown cancels it"; the failure mode is safe (clear parked, handover kept). PROBES §7 shows the mod's own prompts never reach its `prompt.submit`, so the `plugin` exclusion is correct as written.
- **O1 route (b) — a queued instruction prompt survives a manual `/clear`.** Unverified engine behaviour (no probe); folded into R1-01 as a note, not graded on its own.
