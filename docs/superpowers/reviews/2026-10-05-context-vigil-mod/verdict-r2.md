## Rejected findings (NOT REAL for this merge), with reasons

- **S1 — phone sessions get no notice/countdown.** Accepted limit for this merge (PROBES §1, SMOKES #4); fixed on the stacked branch. Same as R1 S7/O10.
- **S4 — an attended `/vho` clear lands after the person sent a new message.** Re-litigates R1 S10: spec §2 "Requested handovers are attended by definition", test shell-handover.test.tsx:178 codifies it. What happens to a prompt queued behind a mod-run `/clear` is unprobed engine behaviour — add it to the R2-02 probe, not a defect here.
- **S6 (main half) — a stale/parked handover is injected on a later manual `/clear`.** Ratified R1-10: "always inject `pending.markdown` as today … submit the resume only if fresh"; the code does exactly that (`resumeStale` notice at :711). Only the un-noticed `limit` leak survives, as R2-17.
- **S11(b) — a bare digit into an empty box presses a bar button.** Spec §3 documents it and makes the bar threshold-only for that reason; by design.
- **S12 — early stop acts regardless of presence; a handover in flight makes the limit handover a null-path resume.** Spec §5 puts no presence condition on the early-stop *handover* (R1-12 added presence to the *resume* only); the instruction is queued until idle so it interrupts no turn. In-flight case: the in-flight handover's tool call writes the file the early stop wanted; the resume then says "no handover was written before the stop" — a wording nit, no loss. The owner may want `limitResumeText` to name the in-flight file (`job.path ?? pending?.path` already does when it is still pending).
- **S13 — `install.sh` bakes the checkout path; non-atomic `cat > file`.** The script lists *this folder* by design (README, spec §7); a worktree path is the owner's choice; two checkouts installed twice is a usage error the `status` line exposes. `cat "$tmp" > "$file"` is the R1-16 ratified write (keeps the dotfiles symlink and mode); a crash inside a ~1 KB `cat` is negligible. Optional later: `mv` onto `readlink -f "$file"` with the mode restored — atomic and symlink-safe.
